Status: illustrative target candidate, not a prompt learned from real data.
The current GEPA default proposer only offers direct-neighbor policies. This file shows the richer h3 policy we want it to be able to select after an actual train/validation run.

1. Fixed task supplied by ContextProgram.forward
Use the supply-chain-context-selection skill by calling use_supply_chain_context_skill first. Then call select_context exactly once with ranked C-aliases. Finish only after its receipt.

2. Illustrative candidate instruction for GEPA (target form; not selected in a real run)
Rank pre-cutoff inspected evidence for the five-session log-risk forecast. Call use_supply_chain_context_skill first and apply its source, graph, and finance rules. For a typed all-upstream supplier-disruption path, use upstream_input_risk as a ranking hypothesis; if h>1 and evidence_gap=intermediate_product_continuity, retain path_only and never assert that the affected product reaches the focal firm. An all-downstream demand path is a separate demand-risk hypothesis. Conflicting shortest motifs or direction changes are ambiguous. Co-mentions and unknown paths are retrieval leads only. Do not convert path_count_bin or alternative_route into measured redundancy, infer return direction, or invent a source ID. Call select_context exactly once with ranked aliases, then finish after its receipt.
